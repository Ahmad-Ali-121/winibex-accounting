# API

Node, Express, MariaDB. REST over JSON. Base path `/api/v1`.

Status: Phase 0 and Phase 1 endpoints built and tested. 416 API tests: 413
pass and 3 skip, the argon2 tests, until that package is installed. Updated
2026-10-28 for batch C (decision 065).

## Conventions

### Money in JSON
Always an object, never a bare number:

```json
{ "minor": 12000000, "currency": "PKR" }
```

`minor` is an integer. Floats in a money field are rejected by validation.

### Dates
`YYYY-MM-DD` for accounting dates. ISO 8601 UTC for timestamps.

The business date is Pakistan's. "Today" for the future-date block, "more
than 90 days ago" for the backdated warning, and "this month" on the
dashboard are all judged in Asia/Karachi, in `core/dates.js`. Timestamps stay
UTC. Decision 057.

### Idempotency
Every request that creates or posts money carries an `Idempotency-Key` header,
a UUID generated by the client when the form opens. The server stores the key
with the result for 24 hours and returns the same result for a repeat. This is
what stops a double tap or a flaky mobile connection from posting the same
expense twice.

A repeat must be the same request. The server keeps a SHA-256 fingerprint of
the body with each key (migration 006), and the same key with a different
body is refused with 409 `IDEMPOTENCY_KEY_REUSED`, never answered with the
first result. To change a draft that already exists, edit it with
`PATCH /transactions/:id`. Decision 059, defect F7.

### Errors
```json
{
  "error": {
    "code": "UNBALANCED_JOURNAL",
    "message": "Debits and credits do not match.",
    "field": null,
    "details": { "debit": 500000, "credit": 450000 }
  }
}
```

`code` is stable and machine-readable. `message` is safe to show a user, and
the app shows it as sent for any 4xx refusal, because it names the actual
problem ("It holds PKR 9,700 today."). A 5xx or no answer gets the app's own
wording. FRONTEND.md.

Validation warnings are not errors. A create request with warnings returns
`409` with the warnings listed. The client shows them, and resubmits with
`"acknowledged_warnings": ["POSSIBLE_DUPLICATE"]` to proceed.

### Pagination
`?page=1&per_page=50`. Response includes `total`, `page`, `per_page`, and the
totals row for the whole filtered set, not just the page.

### Search
`?q=` searches across description, reference, client name and amount on the
server. Never client-side.

### Auth
- Short-lived access token, sent as `Authorization: Bearer`
- Refresh token: httpOnly secure cookie on web, secure storage on Android
- Passwords hashed with bcrypt now, argon2id switchable (decision 042)
- Rate limit on login
- Every response is scoped by role and the `payroll_visible_to_all` setting

### Transactions in MariaDB
Every write runs inside a MariaDB transaction. The posting engine writes the
transaction, its tax and charge lines, its journal lines and the audit entry
in one unit. Any failure rolls everything back.

### Error codes

Stable, and each maps one to one to an `err` key in `app_en.arb`.

| Code | Status | Meaning |
| --- | --- | --- |
| VALIDATION_FAILED | 400 | the request is malformed, with `field` naming where |
| VALIDATION_WARNINGS | 409 | warnings to confirm, in `details.warnings`. Resubmit with `acknowledged_warnings` |
| NOT_RECONCILED | 400 | the money figures do not agree with each other |
| UNBALANCED_JOURNAL | 400 | debits do not equal credits |
| ENTRY_NOT_EDITABLE | 409 | only a draft can be changed |
| INVALID_STATUS | 409 | that move is not allowed from the current status |
| ALREADY_REVERSED | 409 | an entry is reversed once |
| APPROVAL_LIMIT_EXCEEDED | 403 | above this admin's limit |
| REIMBURSEMENT_EXCEEDS_OWED | 400 | more than the company owes that person |
| MISSING_VENDOR_TAX_ID | 400 | a tax Winibex withholds with no vendor chosen, or a vendor with no NTN or CNIC, so the deduction cannot be reported. Checked at create and edit. Decision 062 |
| TRANSFER_SAME_ACCOUNT | 400 | a transfer needs two different accounts |
| OPENING_ALREADY_EXISTS | 409 | there is only ever one |
| HISTORY_DOES_NOT_RECONCILE | 409 | merge refused, differences in `details` |
| RECEIPT_REQUIRED | 400 | money out at or above `receipt_required_above` has no receipt at posting |
| ALREADY_EXISTS | 409 | a unique value is already used, such as a cheque number on the same account, or an email on `/people` |
| IDEMPOTENCY_KEY_REUSED | 409 | that key was already used by another person, on another address, or with different content |
| UNSUPPORTED_FILE | 400 | a receipt that is not an image or a PDF |
| FILE_TOO_LARGE | 400 | over the upload size limit |
| CASH_BELOW_ZERO, FUTURE_DATE, INACTIVE_ACCOUNT, INACTIVE_CATEGORY, BEFORE_OPENING_DATE, HISTORICAL_AFTER_GO_LIVE, LIVE_BEFORE_GO_LIVE, OPENING_WRONG_DATE | 400 | blocking validation |
| TAX_UNKNOWN, TAX_INACTIVE, TAX_NOT_IN_EFFECT, TAX_WRONG_DIRECTION, TAX_LARGER_THAN_BASE | 400 | a tax line that does not fit its tax. The message names the tax. Decision 061 |
| RATE_AMOUNT_MISMATCH | 400 | foreign amount x rate is more than PKR 1 from the rupees. The message gives the right figure. Decision 061 |
